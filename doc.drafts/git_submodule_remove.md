Чтобы правильно удалить подмодуль (submodule) Git из проекта, необходимо выполнить несколько шагов. Простое удаление папки подмодуля не удалит его конфигурацию из Git, что может привести к ошибкам в будущем. Ниже приведён корректный и безопасный способ удаления подмодуля.

### 1. Подготовка
Убедитесь, что вы находитесь в корневой директории вашего основного репозитория и что у вас нет незакоммиченных изменений (особенно в подмодуле, если вы планируете их сохранить). Если в подмодуле есть нужные изменения, сначала закоммитьте их в сам подмодуль и отправьте (push) в его удалённый репозиторий.

### 2. Деинициализация подмодуля
Команда `git submodule deinit` удаляет запись о подмодуле из рабочей области и очищает его из `.git/config`, а также удаляет содержимое папки подмодуля (но не трогает сам каталог `.git/modules`).

```bash
git submodule deinit -f -- .bat
git submodule deinit -f -- .cmake
```
- `-f` (force) требуется, если подмодуль имеет локальные изменения или если команда без флага отказывается работать.
- Замените `путь/к/подмодулю` на актуальный путь (например, `libs/my-submodule`).

### 3. Удаление записи из .gitmodules
Файл `.gitmodules` хранит соответствие между путями и URL подмодулей. Нужно вручную удалить из него секцию, относящуюся к вашему подмодулю. Проще всего это сделать через редактор, либо воспользоваться командой:

```bash
git config -f .gitmodules --remove-section submodule..bat
git config -f .gitmodules --remove-section submodule..cmake
```

Если такой команды нет, можно открыть `.gitmodules` в текстовом редакторе и удалить блок вида:
```
[submodule "путь/к/подмодулю"]
    path = путь/к/подмодулю
    url = https://...
```

Добавьте файл в индекс:
```bash
git add .gitmodules
```

### 4. Удаление подмодуля из индекса Git
Теперь нужно убрать подмодуль из индекса (staging area), но без удаления физических файлов (если они ещё не удалены). Команда `git rm` с опцией `--cached` убирает объект из индекса, но оставляет файлы в рабочей директории.

```bash
git rm --cached .bat
git rm --cached .cmake
```

Если вы уже удалили папку подмодуля вручную, можно использовать просто `git rm путь/к/подмодулю` – это удалит и из индекса, и из рабочей директории (но она уже пуста).

### 5. Удаление из .git/config (опционально)
Обычно `git submodule deinit` уже очистил соответствующую секцию в файле `.git/config`. Проверьте, не осталось ли там упоминаний о подмодуле. Если остались, удалите их вручную из `.git/config` (без расширения .gitmodules, это локальный конфиг репозитория).

### 6. Физическое удаление папки подмодуля
Если после предыдущих шагов папка подмодуля ещё существует, удалите её обычными средствами ОС:
```bash
rm -rf .bat
rm -rf .cmake
```

### 7. Коммит изменений
После всех изменений нужно зафиксировать результат:
```bash
git add .gitmodules
git add путь/к/подмодулю   # если Git отслеживает удаление файлов
git commit -m "Удалён подмодуль путь/к/подмодулю"
```

### 8. Удаление из .git/modules (необязательно)
В каталоге `.git/modules` остаётся копия Git-объектов удалённого подмодуля. Если вы уверены, что он вам больше не понадобится, можно удалить соответствующую папку вручную:
```bash
rm -rf .git/modules/путь/к/подмодулю
```
Но это не обязательно для корректной работы репозитория.

### Альтернативный способ одной командой (Git версии 2.25+)
В современных версиях Git можно выполнить все основные шаги одной командой:
```bash
git rm .bat
git rm .cmake
```
При использовании `git rm` для подмодуля Git автоматически удалит запись из `.gitmodules`, очистит индекс и пометит удаление. Однако это не всегда деинициализирует подмодуль полностью, и локальная конфигурация может остаться. Поэтому для полной чистки всё же рекомендуется выполнить шаги 1–7.

### Важные замечания
- Не удаляйте папку подмодуля вручную до выполнения команд Git – это может нарушить индексацию.
- Если подмодуль содержит важные данные, которые не были отправлены в его удалённый репозиторий, сохраните их отдельно перед удалением.
- После удаления подмодуля все остальные участники проекта должны выполнить `git submodule sync` и `git submodule update --init` после получения изменений, чтобы привести свои копии в актуальное состояние.

Следуя этим шагам, вы безопасно и правильно удалите подмодуль из вашего Git-проекта.
